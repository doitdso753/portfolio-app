반복 업무를 자동화하고 관리 포인트를 일원화하여 업무 생산성을 높이고 운영 비용을 절감할 수 있습니다.

개발 이슈

이슈
에이블리와 내부 서비스의 데이터 구조가 다르고 일부 데이터는 Open API에서 미제공
해결
Open API를 분석해 마켓 데이터를 내부 공통 모델로 표준화하고 미제공 데이터는 Puppeteer로 수집해 보완했습니다. 다른 마켓에 영향을 주지 않으면서 상품, 주문, 배송 프로세스를 연동했습니다.
이슈
마켓별 정책과 처리 분기가 공통 컴포넌트에 누적되어 마켓이 추가될수록 유지보수가 어려워지는 문제
해결
마켓별 정책과 UI 설정을 JSON Configuration으로 분리하고 공통 컴포넌트는 설정값을 기반으로 렌더링하도록 React 구조를 변경했습니다. 신규 마켓 추가 시 공통 컴포넌트의 변경 범위를 최소화했습니다.
이슈
마켓-표준 상품 카테고리의 연결 관계를 변경할 때마다 개발자가 DB를 직접 수정해야 하는 반복 업무 발생
해결
MUI 기반으로 상품 카테고리를 상위부터 단계적으로 탐색하고 내부 표준 카테고리와 연결할 수 있는 관리 화면을 개발했습니다. Next.js API Routes와 Sequelize 기반으로 API를 구현하고 한 번에 여러 연결 관계를 변경하는 과정에서 일부 데이터만 반영되지 않도록 트랜잭션으로 처리했습니다. 또한 변경 전후 값을 이력으로 저장하여 변경 히스토리를 추적할 수 있도록 구현했습니다.

개발 후 느낀점

MSA 컨테이너 환경에서 Kafka 기반 작업 처리부터 각 도메인 서비스와 외부 API 연동까지 이어지는 전체 데이터 흐름을 다루며 개별 기능보다 서비스 간 책임과 데이터 흐름을 함께 고려하는 관점으로 개발했습니다.

판매 채널 확장에서는 마켓별 차이를 코드에 직접 누적하기보다 공통 모델과 JSON Configuration으로 경계를 분리하는 것이 유지보수성과 확장성을 결정한다는 점을 체감했습니다. 신규 기능을 빠르게 추가하는 것뿐 아니라 기존 구조에 미치는 영향을 최소화하는 설계를 우선하게 되었습니다.

백오피스는 단순한 CRUD 화면이 아니라 운영자가 지속적으로 사용하는 제품이라고 생각합니다. 운영자가 직접 데이터를 변경하는 만큼 실제 업무 흐름, 데이터 정합성, 변경 이력, 오류 발생 시 추적 가능성까지 함께 고려해 설계했습니다.

기술 구성

시스템 구성도

  • UI Service(React)와 Backend/Core Service(Node.js)로 구성된 쇼핑몰 통합관리 서비스입니다.
  • 사용자는 UI Service를 통해 상품, 주문, 배송 관리 기능을 이용하며, UI Bridge가 Backend Service와 연동하여 비즈니스 기능을 제공합니다.
  • Backend Service는 도메인별 API로 구성해 기능별 책임을 분리하고 Kafka 메시지 큐로 Backend Service 작업을 비동기로 처리합니다.
  • Next.js 기반 Admin Service에서 마켓 기초 데이터 등 운영 기능을 관리할 수 있도록 구현했습니다.
  • Docker/Kubernetes 컨테이너 환경에서 서비스를 운영했습니다.
