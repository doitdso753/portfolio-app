여러 온라인 쇼핑몰의 상품, 주문, 배송 등 운영 업무를 통합 관리할 수 있는 솔루션입니다.
반복 업무를 자동화하고 관리 포인트를 일원화하여 업무 생산성을 높이고 운영 비용을 절감할 수 있습니다.

개발 이슈

이슈
에이블리와 내부 서비스의 데이터 구조가 다르고 일부 데이터는 Open API에서 미제공
해결
Open API를 분석해 데이터를 공통 모델로 표준화하고 미제공 데이터는 Puppeteer로 수집해 보완했습니다. 다른 마켓에 영향을 주지 않으면서 상품, 주문, 배송 프로세스를 연동했습니다.
이슈
마켓별 처리 로직이 컴포넌트에 누적되어 마켓이 추가될수록 유지보수가 어려워지는 문제
해결
프론트엔드에서는 마켓별 정책과 설정을 JSON Configuration으로 분리해 신규 마켓 추가 시 공통 컴포넌트의 변경 범위를 최소화했습니다.
이슈
기초 데이터의 등록, 수정이 필요할 때마다 개발자가 직접 DB를 수정해야 하는 반복 업무 발생
해결
택배사, 카테고리 매핑 등 기초 데이터를 직접 관리할 수 있는 백오피스 기능을 구현했습니다.

개발 후 느낀점

MSA 컨테이너 환경에서 Kafka 기반 작업 처리부터 각 도메인 서비스와 외부 API 연동까지 연결되는 전체 데이터 흐름을 이해하여 개발할 수 있었습니다. 마켓마다 다른 데이터 구조와 정책을 표준화해 내부 서비스에 적용하는 설계 방식을 경험할 수 있었습니다.

판매 채널마다 다른 정책을 설정으로 분리하면 기존 구조를 지키면서도 확장성을 확보할 수 있었습니다.

공통 컴포넌트는 재사용 범위와 변경 가능성을 함께 고려해야 과도한 추상화를 피할 수 있었습니다.

클라이언트 상태와 서버 상태의 역할을 구분하면 복잡한 관리 화면도 예측 가능하게 구성할 수 있었습니다.

백오피스도 운영자가 매일 사용하는 제품이므로 업무 흐름과 오류 대응까지 세심하게 설계해야 했습니다.

외부 API의 제약에 대응하려면 대체 수집 방식뿐 아니라 실패 감지와 유지보수 기준도 필요하다는 점을 배웠습니다.

기술 구성

시스템 구성도

  • UI Service(React)와 Backend/Core Service(Node.js)로 구성된 쇼핑몰 통합관리 서비스입니다.
  • 사용자는 UI Service를 통해 상품, 주문, 배송 관리 기능을 이용하며, UI Bridge가 Backend Service와 연동하여 비즈니스 기능을 제공합니다.
  • Backend Service는 도메인별 API로 구성해 기능별 책임을 분리하고 Kafka 메시지 큐로 Backend Service 작업을 비동기로 처리합니다.
  • Next.js 기반 Admin Service에서 마켓 기초 데이터 등 운영 기능을 관리할 수 있도록 구현했습니다.
  • Docker/Kubernetes 컨테이너 환경에서 서비스를 운영했습니다.
